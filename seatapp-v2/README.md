# 자리배치 프로그램 v2

선생님 계정 / 학생 계정을 분리하고, **자리배치 계산 자체를 서버에서 돌려서**
선생님 화면에는 학생이 입력한 원본 정보(MBTI·성적·시력·선호짝꿍 등)가 **절대 전달되지
않고, 최종 좌석 배치 결과만** 보이도록 만든 버전입니다.

## 왜 이런 구조인가

- 학생 로그인은 이메일 없이 **번호 + 4자리 PIN**만 씁니다.
- 자리배치 알고리즘은 서버(Vercel 함수, `api/run-seating.js`)에서만 학생 원본
  데이터를 읽습니다. 계산이 끝나면 "몇 번 자리에 누가 앉는지"만 저장하고, 나머지는
  버립니다. 선생님 화면(Firestore 보안 규칙)에서는 애초에 학생 원본 문서를
  읽을 권한 자체가 없습니다.
- **주의**: 이건 학교 내부에서 서로 신뢰하는 관계를 전제로 한 수준의 보안입니다.
  Firebase 프로젝트 소유자(선생님 본인)가 Firebase 콘솔에 직접 들어가면 당연히
  모든 데이터를 볼 수 있고, 진짜 국가기관급 데이터 격리는 아닙니다. "같은 반
  선생님이 학생 화면 개발자도구를 뒤져서 몰래 보는 것" 정도를 막는 수준이라고
  생각하시면 됩니다.

## 포함된 기능 / 아직 없는 기능

**포함됨**
- 선생님 이메일/비밀번호 회원가입·로그인, 반 생성(여러 반 가능)
- 학생 이름 목록 입력 → 번호+PIN 자동 생성 (한 번만 화면에 표시, 선생님이 나눠줘야 함)
- 학생 번호+PIN 로그인 → 본인 정보 입력/수정 (MBTI, 성적, 키, 시력, 선호위치,
  에어컨, 활동성, 선호짝꿍 1~3지망, 기피짝꿍, 메모)
- 선생님용 가중치 슬라이더(선호짝꿍/성격균형/성적균형/활동성분산/선호위치)
- "배치 실행" → 서버에서 시뮬레이티드 어닐링으로 최적화 → 최종 좌석표만 표시

**v1에 있었지만 이번엔 뺀 것 (필요하면 다음에 추가 가능)**
- 통로/사물함 배치, 고정좌석, 블랙/화이트리스트 수동 지정 UI
- 5가지 전략 동시 실행, 히트맵, 인쇄 모드, 배치 이력, CSV 가져오기
- 학생별 배치 이유 설명 (요청하신 대로 아예 제거)

## 1. Firebase 프로젝트 만들기

1. https://console.firebase.google.com 에서 새 프로젝트 생성
2. **Authentication** → 시작하기 → 로그인 방법에서 **이메일/비밀번호** 사용 설정
   (학생은 이메일 없이 커스텀 토큰으로 로그인하므로 별도 설정 불필요)
3. **Firestore Database** → 데이터베이스 만들기 (프로덕션 모드로 시작해도 됨,
   아래 규칙을 곧 덮어쓸 거라서 상관없음)
4. **Firestore Database → 규칙** 탭에 이 프로젝트의 `firestore.rules` 내용을
   그대로 붙여넣고 게시
5. **프로젝트 설정(⚙️) → 일반 → 내 앱 → 웹 앱 추가** → 나오는 `firebaseConfig`
   객체를 복사해서 `public/index.html` 상단의 `firebaseConfig = { ... }` 부분에
   붙여넣기
6. **프로젝트 설정 → 서비스 계정 → 새 비공개 키 생성** → JSON 파일 다운로드
   (이 파일 안의 `project_id`, `client_email`, `private_key` 세 값을 다음 단계에서 씁니다)

## 2. Vercel에 배포

```bash
npm install          # firebase-admin 설치
vercel                # 처음 배포 (질문에 답하면 됨)
```

Vercel 대시보드 → 프로젝트 → **Settings → Environment Variables** 에 서비스
계정 JSON에서 뽑은 값을 등록:

| 이름 | 값 |
|---|---|
| `FIREBASE_PROJECT_ID` | JSON의 `project_id` |
| `FIREBASE_CLIENT_EMAIL` | JSON의 `client_email` |
| `FIREBASE_PRIVATE_KEY` | JSON의 `private_key` (줄바꿈 그대로 붙여넣기, Vercel이 알아서 처리) |

환경변수 등록 후 **Redeploy** 한 번 해줘야 반영됩니다.

```bash
vercel --prod
```

## 3. 사용 흐름

1. 선생님이 배포된 주소 접속 → 👩‍🏫 선생님 → 회원가입 → 반 만들기 (행/열 입력)
2. "학생 계정 만들기"에 이름 목록 붙여넣기 → 생성된 **번호+PIN 표**를 캡처하거나
   인쇄해서 학생들에게 나눠주기 (반 코드도 같이 전달해야 함, 카드 상단에 표시됨)
3. 학생들이 각자 접속 → 🧑‍🎓 학생 → 반 코드+번호+PIN 로그인 → 정보 입력 후 저장
4. 선생님이 가중치 조절하고 "배치 실행" → 몇 초 후 최종 좌석표 확인

## 참고: 로컬에서 테스트하려면

```bash
vercel dev
```
`api/` 폴더의 서버리스 함수까지 로컬에서 그대로 테스트할 수 있습니다.
